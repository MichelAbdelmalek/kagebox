# Milestone 1.1: Ingest — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn an uploaded or imported chapter (PDF, CBZ or image folder) into stored Pages, Panels in reading order, and Bubbles with OCR text and confidence. Every artifact cites its source page or panel, and anything doubtful lands in the review queue.

**Architecture:** A Prefect `ingest_flow(chapter_id)` running on `worker-cpu`. Pages are rasterized in a resource-limited child process (PDF) or read through the Phase 0 safe archive reader (CBZ). Panels come from classical OpenCV gutter detection plus recursive XY-cut reading order. Bubbles come from the pinned RT-DETRv2 bubble detector. OCR uses manga-ocr (JA) or PP-OCRv5 (EN/KO). Every model loads through a verify-then-load helper. Results go to Postgres (metadata) and SeaweedFS (images). The API creates chapters, accepts uploads or server-side imports, starts the flow through Prefect's REST API, and serves pages, panels and bubbles with signed image URLs.

**Tech Stack:** Python 3.11, Pydantic v2 (strict), SQLAlchemy 2 + Alembic, FastAPI, Prefect 3.8, OpenCV 4.14, pypdfium2 5.15, transformers 5.23 (CPU), SeaweedFS S3.

**Spec:** `CLAUDE.md` (Pipeline stage 1, Security requirements), `docs/plans/phase-1.md` (milestone 1.1), `docs/plans/phase-1-model-audit.md` (decisions 1–3), `docs/sample-chapter-source.md`.

## Global Constraints

- Python 3.11; every tool runs in Docker (`make test`, `make lint`); nothing is installed on the host.
- No new dependencies beyond what `pyproject.toml` already locks (pypdfium2 was added for this milestone).
- Schemas: strict Pydantic v2 (`pipeline/common/schemas`). A non-null `Cited` value must cite its own panel; unknown fields stay `null`, never guessed.
- OCR confidence below **0.90** sets `Bubble.needs_review` and creates a ReviewItem (`OCR_CONFIDENCE_MIN`).
- Models load **only** from `/models/<name>/<revision>` after every pinned file is re-verified (`verify_file`), with `local_files_only=True, use_safetensors=True, trust_remote_code=False, dtype=float32`, and no network (`HF_HUB_OFFLINE=1`).
- Ingest refuses unless the project's RightsRecord is `approved` and unexpired (`require_render_allowed`).
- OCR text and file names are untrusted data. They are never interpolated into a shell, a path or a query (use bound parameters and argument lists).
- Upload limit stays **200 MB** over HTTP. Larger sources use server-side import from the read-only `/imports` mount, by bare file name only.
- PDF limits: at most **1000** pages; render so the long side is at most **3000 px**; the child process gets **2 GB** of address space and **60 s** of CPU per page; encrypted PDFs are refused.
- Reading order: `manga_rtl` means right-to-left within a row; `comic_ltr` means left-to-right; `manhwa_vertical` is sliced into pages at gutters, then read left-to-right.

## Review Focus

1. **Full-bleed and spread pages** (sample pages 4–5, 6, 34–37): a borderless page must give **one** panel covering the page, not dozens of fragments. *Test in Task 4.*
2. **Free text outside bubbles** (vertical narration on page 34, `text_free`): it must still be OCR'd and assigned to the panel it sits in. *Test in Task 5.*
3. **Hostile or odd PDFs** (encrypted, more than 1000 pages, a huge page size, a renderer crash): refused with a clear error, the worker survives, and no partial chapter is left `ready`. *Test in Task 3.*
4. **A bubble overlapping two panels**: it goes to the panel with the largest overlap, never to both. *Test in Task 5.*
5. **A bad `page_range`** (reversed, out of bounds, malformed): 422 from the API before any work starts. *Test in Task 8.*

### Task 4: Panel detection and reading order

**Files:**
- Create: `pipeline/ingest/panels.py`
- Test: `tests/unit/test_panels.py` (synthetic pages drawn with OpenCV: black borders on white, plus a full-bleed grey page)

**Interfaces — Produces:**
- `detect_panels(img: np.ndarray) -> list[BBox]` (grayscale or RGB input)
- `reading_order(boxes: list[BBox], direction: Literal['rtl','ltr']) -> list[int]` (a permutation)
- `slice_strip(img: np.ndarray, max_height: int = 3000) -> list[tuple[int, int]]` (y ranges cut at the widest white gutters, for manhwa)

**Algorithm (decided):**
1. Otsu threshold to an ink mask; dilate ink 3×3 to close hairline gaps.
2. Flood-fill white from the page border to get the gutter mask. Panels are the connected components of non-gutter pixels with area ≥ 2% of the page.
3. No component, or one ≥ 90% of the page, means a single full-page panel.
4. Order by recursive XY-cut: split on the widest horizontal gap first (top to bottom), then vertical gaps (right to left for `rtl`). With no gap (overlapping boxes), fall back to sorting by `(top // (h/20), -right)` for rtl or `(top // (h/20), left)` for ltr.

**Interfaces — Produces:**

- `token_confidence(probs: Sequence[float]) -> float`, which returns 0.0 for an empty sequence.

## Decisions taken in this plan (from the spec and the source)

- **Chapter 1 = PDF pages 3–58** (`第1話 研修医の夜`; colour pages 3–6, spread 4–5; chapter 2's cold open starts on page 61).
- **Speaker linking moves to milestone 1.3.** It needs character detections from the series bible. Until then, `Bubble.speaker` stays `null` (no evidence) rather than guessed. This keeps the brief's no-hallucination rule; `docs/plans/phase-1.md` gets updated to match.
- **Large sources use server-side import** from a read-only mount, by bare file name. HTTP upload keeps the 200 MB cap.
